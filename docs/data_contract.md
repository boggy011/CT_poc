# RetPack Data Contract — v0.9 (draft for ABI AI team review)

Status: **draft**. Becomes v1.0 when ABI input 3 (status enum) and input 4 (reference view DDL) are confirmed. Everything marked *assumed* is the portal's proposal and can change without code changes on the portal side; everything else is what the portal writes and the AI cross-check may read.

## 1. Tables the portal writes

### 1.1 `submission_event` (append-only)

| Column | Type (Delta / Postgres) | Meaning |
|---|---|---|
| `submission_id` | STRING / TEXT | UUIDv7, generated by the portal. Time-ordered. |
| `account_id` | STRING / TEXT | Payer / sold-to. Identical on every event of one submission. Tenant key for row filters. |
| `seq` | INT / INTEGER | 1-based, gapless per submission. `(submission_id, seq)` is unique. |
| `event_type` | STRING / TEXT | One of the values in §2. |
| `actor` | STRING / TEXT | Email of the user, or `cpi-dispatch@system.local` for the job. |
| `actor_role` | STRING / TEXT | `CUSTOMER`, `INTERNAL`, `SYSTEM`. |
| `occurred_at` | TIMESTAMP / TIMESTAMPTZ | When the action happened (UTC). |
| `payload` | STRING (JSON) / JSONB | Shape depends on `event_type`; see §2. |
| `ingested_at` | TIMESTAMP / TIMESTAMPTZ | Write time. |

Rows are never updated or deleted by the portal. Current state is derived by folding a submission's events in `seq` order (§3). Consumers that need current state should either fold the same way or read the derived view the portal team will publish once the enum is frozen.

### 1.2 Attachments

PDF bytes live in a Unity Catalog Volume at `/Volumes/<catalog>/<schema>/attachments/<account_id>/<submission_id>/<doc_type>_<seq>.pdf`. Metadata is embedded in events (§2, `AttachmentMeta`); there is no separate attachment table in Wave 1.

`AttachmentMeta` (JSON object):

| Field | Type | Notes |
|---|---|---|
| `submission_id`, `account_id` | string | as above |
| `doc_type` | string | from the attachment policy (*assumed*: `delivery_note`, `other`; ABI input 2) |
| `seq` | int | 1-based per submission |
| `original_filename` | string | sanitised, ≤ 255 chars |
| `storage_path` | string | Volume path |
| `sha256` | string | hex, duplicate detection |
| `size_bytes`, `page_count` | int | |
| `has_text_layer` | bool | false means scanned: the AI cross-check will find no text |
| `uploaded_at` | ISO-8601 string | |
| `uploaded_by` | string | email |

## 2. Event types and payloads

| `event_type` | Written by | `payload` |
|---|---|---|
| `SUBMITTED` | customer (portal) | `{"values": {<field_name>: <value>}, "attachments": [AttachmentMeta, ...]}`. Always `seq = 1`. Field names and value types come from the field spec (§5). |
| `ATTACHMENT_ADDED` | reserved | `AttachmentMeta` as an object. Not produced in Wave 1. |
| `FIELD_OVERWRITTEN` | internal team | `{"field": <name>, "prior": <value or null>, "new": <value or null>}`. `null` new value clears the field. |
| `VALIDATED` | internal team | `{}`. Releases the request to the CPI dispatch job. |
| `CPI_DISPATCHED` | job | `{"idempotency_key": "<submission_id>:<validated_seq>", "attempt": <int>}` |
| `CPI_SUCCEEDED` | job | `{"cpi_reference": <string>, "attempt": <int>}` |
| `CPI_FAILED` | job | `{"error": <string>, "attempt": <int>, "terminal": <bool>}`. `terminal: true` is the dead letter. |
| `CREDIT_NOTE_RECORDED` | job / ABI process (*to confirm*) | `{"credit_note_no": <string>, "outcome": <string>}` |

Value types inside `values`: string for string/text/enum fields, int for integer, decimal as a **string** with fixed decimals (e.g. `"1.50"`), date as `"YYYY-MM-DD"`.

## 3. Status derivation (placeholder enum — ABI input 3)

| Status | Derived when |
|---|---|
| `SUBMITTED` | after `SUBMITTED`, before any `VALIDATED` |
| `VALIDATED` | after `VALIDATED`, before any `CPI_DISPATCHED`; also after a re-`VALIDATED` following a terminal `CPI_FAILED` |
| `CPI_PENDING` | after `CPI_DISPATCHED`, or after a non-terminal `CPI_FAILED` |
| `CPI_DONE` | after `CPI_SUCCEEDED` |
| `CPI_FAILED` | after a terminal `CPI_FAILED` |

`CREDIT_NOTE_RECORDED` does not change status. Customers see only "Not validated" (`SUBMITTED`) or "Validated" (everything else) plus the credit note.

**Decision to confirm with ABI:** a terminal `CPI_FAILED` request may be corrected (`FIELD_OVERWRITTEN`) and re-validated by the internal team; the re-`VALIDATED` event re-arms dispatch with a new idempotency key.

## 4. Reference views the portal reads (*assumed* — ABI input 4)

All under `<catalog>.<ref_schema>`. The portal only ever `SELECT`s from these.

| View | Columns | Used for |
|---|---|---|
| `ref_account` | `account_id STRING, name STRING, sales_org STRING` | account dropdown, names on screens |
| `ref_sku` | `account_id STRING, sku_code STRING, description STRING` | SKU dropdown per account (4–5 rows each) |
| `ref_sales_org` | `code STRING, name STRING` | sales-org dropdown (4 rows) |
| `ref_email_account` | `email STRING, account_id STRING` | FR-01 email → account resolution, on every request |
| `ref_internal_user` | `email STRING` | internal role (alternatively a workspace group; ABI input 6) |
| `keg_balance` | `account_id STRING, shipped INT, returned INT, as_of TIMESTAMP` | FR-11 plain-number balance (ownership: Q6) |

Different names or columns are a one-line configuration change per table on the portal side.

## 5. Field specification

Field names, types and rules are configuration (`config/fields/*.yaml`). The placeholder spec will be replaced by `abi_v1.yaml` from the ABI mapping Excel (input 1). The `values` object in `SUBMITTED` uses exactly those field names.

## 6. Guarantees

- `(submission_id, seq)` unique; `seq` gapless from 1.
- Every event of a submission carries the same `account_id`.
- One user action = one event. A submit with N PDFs is one `SUBMITTED` event.
- Payloads never contain PDF bytes.
- Original customer input is preserved: `SUBMITTED.values` is never modified; corrections are `FIELD_OVERWRITTEN` events carrying prior and new values.
